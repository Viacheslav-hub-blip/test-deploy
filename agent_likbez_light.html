Инструмент read_file

deep_agent/prompts/tool_description_prompt.py 
read_file
---
Описание:
Читает текстовый файл.

Вход:
- `file_path`: абсолютный путь файла в файловом namespace tools.
- `offset`: первая строка для чтения при pagination.
- `limit`: максимальное число строк.
- Используй канонические POSIX workspace paths,
  например `/report.md`; не передавай Windows paths.

Выход:
- запрошенный текстовый фрагмент и metadata
  о прочитанном диапазоне;
- content может отображаться с номерами строк или
  служебными notices; эти prefixes не являются
  частью file content.
deepagents/middleware/filesystem.py 
def sync_read_file(
    file_path,
    runtime,
    offset=DEFAULT_READ_OFFSET,
    limit=DEFAULT_READ_LIMIT,
) -> ToolMessage:
    """Synchronous wrapper for read_file tool."""
    resolved_backend = self._get_backend(runtime)
    try:
        validated_path = validate_path(file_path)
    except ValueError as e:
        return ToolMessage(
            content=f"Error: {e}",
            name="read_file",
            tool_call_id=runtime.tool_call_id,
            status="error",
        )
    if _check_fs_permission(self._permissions, "read", validated_path) == "deny":
        return ToolMessage(
            content=f"Error: permission denied for read on {validated_path}",
            name="read_file",
            tool_call_id=runtime.tool_call_id,
            status="error",
        )
    read_result = resolved_backend.read(validated_path, offset=offset, limit=limit)
    return _handle_read_result(
        read_result, validated_path, runtime.tool_call_id, offset, limit
    )

Описание:
Создает и поддерживает актуальный checklist
текущей задачи.

Вход:
- список задач с названием, статусом и описанием

Выход:
- обновленный план, доступный агенту
  на следующих шагах выполнения.

- задачу нужно разбить на несколько

- статус запланированных шагов изменился;
- все задачи выполнены,
  необходимо завершить выполнение.

deepagent15

Технический запрос

Структура
  • результат;
  • источники;
  • границы изменений;
  • пограничные случаи;
  • проверка;
  • маршрут tools и subagents.
Полный пример 
Добавь экспорт активных клиентов.

Источник:
- таблица prod.clients;
- период 2026-09-01..2026-09-21;
- поле даты event_dt;
- поля результата client_id и segment.

Результат:
- /artifacts/clients.parquet;
- одна строка на client_id;
- пустой результат сохраняется как parquet
  с той же схемой.

Маршрут:
1. Передай data-retrieval-agent проверку схемы
   и выгрузку таблицы.
2. Для проверки количества строк используй python.
3. Не изменяй код проекта.
4. Верни путь к artifact, число строк,
   применённый фильтр и ограничения.

# Цель
Перенести расчёт X из legacy.py в reports/x.py.

# Границы
Можно менять:
- reports/x.py
- tests/test_x.py

Нельзя менять:
- публичную сигнатуру calculate_x
- формат итогового DataFrame

# Найденный контекст
- calculate_x вызывается из pipeline/main.py
- SparkSession создаётся в spark/session.py
- стиль функций: reports/base.py

# Пограничные случаи
- пустой DataFrame
- null в source_value
- дубликаты по client_id

# Критерии готовности
- calculate_x сохраняет сигнатуру
- схема результата не изменилась
- контрольный набор даёт тот же результат
- тесты reports проходят

# Следующий запрос
Реализуй задачу по /SPEC.md.
Перед изменением кода прочитай все файлы,
перечисленные в разделе «Найденный контекст».

Оптимизация запросов

Пространство для контекста

  • SkillПовторяемый процесс.
  • user_profile.mdПредпочтения пользователя.
  • WikiПредметные знания и карта документов.

Стоит указать в запросе

  • желаемый результат;
  • границы и запреты;
  • нужные skill, tool и subagent;
  • способ проверки;
  • состав финального ответа.
Перед началом работы:
- используй материалы только из /input/;
- фиксируй проверки и их результаты,
  чтобы не повторять выполненные действия;
- полные результаты сохраняй в /artifacts/.

Маршрут:
- поиск и выгрузка данных:
  data-retrieval-agent
  + table-data-retrieval-workflow;
- изменения кода: coding-agent.

Готово, когда: <критерий готовности>.
Проверка: <тест, отчёт или artifact>.

Финальный ответ:
- что изменено;
- какие проверки выполнены;
- пути к artifacts;
- ограничения.
